## Introducción
**Sauna** es una maquina de **HackTheBox** enfocada en entornos **Active Directory**.
El acceso inicial se obtiene a traves de **OSINT desde la web corporativa** de Egotistical
Bank, donde se identifican nombres de empleados que permiten construir posibles usernames
del dominio. Mediante **AS-REP Roasting** se captura el hash de `fsmith`, cuya contraseña
se crackea offilne. Una vez dentro, se descubre que el registro de Windows tiene configurado
**AutoLogon** con las credenciales en texto claro de la cuenta de servicio `svc_loanmgr`.
El analisis con **BloodHound** revela que esta cuenta tiene el permiso extendido
`DS-Replication-Get-Changes-All` sobre el objeto del dominio, lo que permite ejecutar un
ataque de **DCSync** para volcar todos los hashes y comprometer el dominio completamente
mediante **Pass-The-Hash**.

## AS-REP Roasting — Captura del hash de fsmith

### ¿Qué es AS-REP Roasting?

El flujo normal de **Kerberos** funciona asi:

1. Cliente → AS-REQ (con pre-autenticacion cifrada con la contraseña)
2. DC → verifica que la pre-auth es correcta
3. DC → AS-REP (TGT cifrado)


La **pre-autenticacion** es lo que impide que cualquiera solicite un TGT de otro
usuario, ya que demuestra que el cliente conoce la contraseña antes de recibir el ticket.

Sin embargo, si un usuario tiene el atributo `UF_DONT_REQUIRE_PREAUTH` configurado
(una mala practica pensada para compatibilidad con aplicaciones antiguas), el flujo
cambia:

1. Ciente → AS-REQ (sin pre-autenticacion, solo el username)
2. DC → AS-REQ (TGT cifrado con la contraseña del usuario - sin verificación)

El DC entrega el TGT cifrado **a cualquiera que lo pida**, sin verificar que 
realmente conoce la  contraseña. Nosotros capturamos ese AS-REP y lo crackeamos
offilne porque está cifrado con el hash NT de la contraseña del usuario.

```bash
GetNPUsers.py EGOTISTICAL-BANK.LOCAL/fsmith -dc-ip 10.129.95.180 -no-pass
```

```
[*] Getting TGT for fsmith
krb5asrep$23
fsmith@EGOTISTICAL-BANK.LOCAL:d02d1b983647023c877a4b7b4dafd444$0f9dfdd8b43c...
```

> El usuario `fsmith` tiene `UF_DONT_REQUIRE_PREAUTH` configurado. El DC entrego el AS-REP
> sin ninguna verificacion. Ahora solo necesitamos crackearlo offilne.

### Crackeo de hash AS-REP

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hash
```

```
Thestrokes23     (krb5asrep$23
fsmith@EGOTISTICAL-BANK.LOCAL)
```

**Contraseña de fsmith:** `Thestrokes23`

## Kerberoasting — Captura del TGS de HSmith

### Sincronización del reloj

El escaneo inicial detecto un desfase de casi 7 hoas. Kerberos requiere que la diferencia
entre el cliente y KDC sea menor a **5 minutos**. Sin sincronizacion, el DC rechazara todo los tickets con el error `KRB_AP_ERR_SKEW`:

```bash
sudo ntpdate 10.129.95.180
```

### ¿Qué es Kerberoasting?

Cuando un usuario solicita acceso a un servicio identificado por un **SPN**, el KDC emite un **Ticket de Servicio (TGS)** cifrado con el hash NTLM de la cuenta que tiene ese SPN.
El punto critico es que **cualquier usuario autenticado** puede solicitar ese TGS — el KDC no verifica si realmente vas a usar el servicio.

Capturamos ese TGSy lo crackeamos offline. Si la contraseña de la cuenta de servicio es debil, obtenemos acceso a esa cuenta sin hacer ningun ruido adicional en la red.

```bash
nxc ldap $IP -u fsmith -p 'Thestrokes23' -d EGOTISTICAL-BANK.LOCAL --kerberoasting roast.txt
```


## Post-Explotación — AutoLogon en el registro

Una vez dentro, realizamos enumeracion básica del sistema. Una tecnica fundamental en post-explotacion de Windows es revisar el registro en busca de **Autologon** configurado.

**¿Qué es AutoLogon?**

Windows permite configurar un inicio de sesion automatico almacenando credenciales en el registro bajo clave `Winlogon`. El objetivo es que el sistema arranque directamente sin pedir contraseña. El problema es que las credenciales se almacenan **en texto claro**
y cualquier usuario con acceso al sistema puede leerlas:

```powershell
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon"
```

```
DefaultUserName    EGOTISTICALBANK\svc_loanmanager
DefaultPassword    Moneymakestheworldgoround!
```

> El sistema tiene **AutoLogon** configurado con las credenciales de `svc_loanmgr` en texto claro. Esta es una misconfiguration critica: cualquier usuario con acceso local o remoto puede leer esta clave del registro y obtener las credenciales de la cuenta de servicio.


Verificamos que las credenciales son válidas:

```bash
nxc smb $IP -u 'svc_loanmgr' -p 'Moneymakestheworldgoround!' -d EGOTISTICAL-BANK.LOCAL
```

```
[+] EGOTISTICAL-BANK.LOCAL\svc_loanmgr:Moneymakestheworldgoround!
```

## Escalada de Privilegios — DCSync

### ¿Qué es DS-Replication-Get-Changes-All?

Es un **Extended Right** (permiso extendido) en Active Directory que se aplica directamente sobre el objeto del dominio. **No es un grupo, no es administrador, no es Domain Admin.** Es un permiso ACL especifico que controla quien puede solicitar replicacion de credenciales al Domain Controller.

**¿Por qué existe este permiso?**

Los Domain Controlles necesitan replicarse entre si constantemente para manterner coherencia. Este proceso usa el protocolo **DRSUAPI (Directory Replication Service Remote Protocol)**. Cuando un DC nuevo se une al dominio, solicita a los otros DCs que le entreguen todo los hashes. Los dos permisos que hacen posible son:

- `DS-Replication-Get-Changes` — permite replicar objetos del directorio.
- `DS-Replication-Get-Changes-All` — añade la capacidad de replicar **atributos secretos**, incluyendo los hashes NT de las contraseñas.

Si una cuenta que no es un DC tiene estos permisos (como `svc_loanmgr`), puede impersonar a un DC legitimo y solicitar al DC real que le entregue todos los hashes del dominio. Esto es lo que llamamos **DCSync** — el DC no sabe que no esta hablando con otro DC real.

**¿Qué diferencia hay con extraer NTDS.dit directamente?**

Con DCSync no necesitamos acceso fisico al DC, no necesitamos crear un Shadow Copy, no necesitamos copiar archivos del sistema. Todo ocurre a traves del protocolo de replicacion normal de Active Directory, lo que lo hace mucho mas silencioso y dificil de dectetar.

## Acceso Final como Administrador

Con el hash del Administrador ejecutamos **Pass-The-Hash** usando `psexec.py`, que utiliza el protocolo SMB para autenticarse con el hash NTLM sin necesitar la contraseña en texto claro:

```bash
psexec.py EGOTISTICAL-BANK.LOCAL/Administrator@10.129.95.180 -hashes aad3b435b51404eeaad3b435b51404ee:823452073d75b9d1cf70ebdf86c7f98e
```
